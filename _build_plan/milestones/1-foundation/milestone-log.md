# Milestone 1 — Foundation

## What's new in the app

- **You can create an account.** Sign up with your name, email, password, and role (Executive, Product Manager, Engineer, or Designer). You're signed in automatically as soon as the account is created.
- **You can log in and out.** Standard email and password sign-in, with a user menu in the top-right to log out.
- **You can reset a forgotten password.** Request a reset link by email, click through, and set a new password. Old passwords stop working immediately, and each link can only be used once.
- **Your role is visible throughout the app.** It shows as a badge in the navigation bar and in your user menu.
- **The app knows what altitude you work at.** The dashboard tells you which level of detail work items will open at for your role — Roadmap for Executives, PRD for Product Managers, Spec for Engineers and Designers.
- **You can switch between light and dark mode.** A theme toggle in the navigation offers Light, Dark, or System, and your choice persists across page loads and sessions.
- **You can edit your profile.** A settings page lets you change your name, set an avatar by pasting an image URL (with a live preview), and change your role. Changes appear in the navigation bar immediately.
- **Pages are protected.** Visiting any signed-in page while logged out sends you to the login screen and returns you where you were headed after signing in.

**Routes**

## Decisions made during implementation

1. **Next.js 16, not 15.** `create-next-app@latest` installed 16.3.0. Two consequences the next milestone must know: **`middleware.ts` is now `proxy.ts`** (same functionality, and it defaults to the **Node.js runtime**, so there is no Edge constraint on auth code), and `params`/`searchParams`/`cookies()` are **async-only**. Typed route helpers (`PageProps<"/route">`, `LayoutProps<"/">`) are generated by `next typegen` and run automatically during build.

2. **Node pinned to 22.22.3 (LTS), not 20.** Several transitive dependencies require Node ≥ 20.19; the machine's default was 20.18.0. `.nvmrc` pins 22.22.3 — run `nvm use` before `npm install`.

3. **Postgres is on host port 5433, not 5432.** Port 5432 was already occupied by another project's running container (`camber-db`). That container was left untouched. `DATABASE_URL` and `docker-compose.yml` both use 5433.

4. **Profile data is read from the database, not the JWT.** This was a bug fix, and it matters for milestone 2. Originally `role` was stored in the JWT and read from the session. Changing your role in settings did **not** update it — `useSession().update()` with no payload does not reissue the token, so the navigation kept showing the old role even after a reload. The JWT now carries **only the user id**; `getCurrentUser()` in `src/lib/session.ts` loads the user row from the database. **Milestone 2 must use `getCurrentUser()` for role-based view and edit rights — do not read `session.user.role`, it no longer exists.**

5. **shadcn v4 has no `form` component.** The registry now ships `field` (`Field`, `FieldLabel`, `FieldError`, `FieldGroup`, `FieldDescription`). All forms use `react-hook-form` + `zodResolver` directly with these primitives. `FieldError` takes an `errors` array, which accepts react-hook-form's error objects as-is. Follow this pattern for new forms.

6. **`useWatch`, not `watch()`.** React Compiler is on by default and cannot memoize react-hook-form's `watch()`. Use `useWatch({ control, name })` for live form values.

7. **Client components calling `useSearchParams()` must be wrapped in `<Suspense>`** or the production build fails while prerendering. This bit the login page (it reads `callbackUrl`).

8. **Route protection is two-layered.** `src/proxy.ts` redirects unauthenticated requests and bounces signed-in users away from auth pages; `(app)/layout.tsx` independently re-checks via `getCurrentUser()`. Keep both.

9. **Password reset does not leak account existence.** The request endpoint returns an identical success response whether or not the email matches a user. Tokens are single-use (all of a user's tokens are deleted on successful reset) and expire after 1 hour.

10. **Email is not editable** on the settings page — changing a login identifier implies a re-verification flow that is out of scope for this milestone.

## What the next milestone needs to know

- **Use `getCurrentUser()`** (`src/lib/session.ts`) in server components to get the signed-in user including their current `role`. It returns `null` when signed out.
- **Add new UI components** with `npx shadcn@latest add @shadcn/<name>` (the `@shadcn/` namespace prefix is required in v4).
- **The `(app)` route group** is the authenticated shell — put the kanban board and work-item routes there and they inherit the nav bar and auth gate for free.
- **`ALTITUDE_BY_ROLE`** currently lives inline in `src/app/(app)/dashboard/page.tsx`. Milestone 2 needs this mapping for default-altitude tab selection; move it into `src/lib/roles.ts` rather than duplicating it.
- **The `account`, `session`, and `verification_token` tables are intentionally unused** right now. They exist so GitHub OAuth can be added in milestone 5 without a migration.
- **Adding background jobs** (Inngest, needed from milestone 4 onward) has no structural blockers: add `src/inngest/` and `src/app/api/inngest/route.ts`.

## Deviations from the PRD

- **Node 22 instead of Node 20** and **Postgres on 5433 instead of 5432** — both environment constraints, explained above. No product impact.
- **`role` removed from the session token.** The PRD did not specify where role lives; storing it in the JWT proved incorrect once role became editable. Behaviour matches the PRD; the mechanism differs.
- Everything in the milestone's "What gets built" list was delivered. Nothing was cut.

## Verification

Verified in a real browser (headless Chrome driving the running dev server), plus HTTP-level checks of the API routes:

| Done-when criterion | Result |
| --- | --- |
| Sign up with email + password | Pass — auto-signed in, lands on `/dashboard` |
| Role is saved | Pass — persisted, shown in nav and settings; Executive→Roadmap, PM→PRD, Engineer/Designer→Spec |
| Log out and back in | Pass |
| Reset a forgotten password by email | Pass — link delivered (console in dev), new password works, old password rejected, token single-use |
| Toggle light/dark mode | Pass — persists across reload and re-login |
| Edit name, avatar, role in settings | Pass — persists and updates the nav immediately |

Also verified: unauthenticated access to `/dashboard` and `/settings` redirects to `/login` with a `callbackUrl`; signed-in users hitting `/login` are redirected to `/dashboard`; duplicate signup returns 409; short passwords rejected; password reset requests are indistinguishable for known vs. unknown emails. `npm run lint`, `npx tsc --noEmit`, and `npm run build` all pass clean, with no browser console errors.

Test accounts created during verification were deleted; the dev database is empty.

**Not verified:** real email delivery through Resend (no API key was configured — the flow was exercised via the dev console fallback). Add `RESEND_API_KEY` and a verified sending domain to confirm end-to-end delivery.

**Known issue:** `npm audit` reports 4 moderate advisories from `esbuild` via `drizzle-kit`. This is dev-only migration tooling, never shipped to production; the only fix offered is a major downgrade to drizzle-kit 0.18, so it was left in place.
